Staff Control Home

Private Game Request Operations Center

This page is used by ⁅𝐓𝐡𝐲𝐓☣︎𝐱𝐢𝐜𝐆𝐚𝐦𝐞𝐫⁆ and currently verified Twitch moderators to manage the complete game-request workflow. Staff can control availability, review requests, correct eligible game or system details, record agreed schedules, review history, and confirm that Discord notifications were delivered.

Staff access is operational access. Every decision must follow the viewer-facing request rules, preserve the approved payment bracket, and include an accurate explanation whenever the system requires one.

How to Use Staff Control

Staff Workflow

  1. Check the status summaryConfirm that request services, the viewer slot, and Discord delivery show the expected state.
  2. Review the active requestVerify the viewer, game, system, request choice, price, and note before approving or changing anything.
  3. Record the decision accuratelyUse the correct control and provide a clear reason for denials, cancellations, corrections, or schedule changes.
  4. Confirm the resultCheck Request Records, Archive, and Admin to ensure the database and Discord received the update.

Required Conduct

Staff Rules

Access and privacy

  • Only the owner and currently verified Twitch moderators may use Staff Control.
  • Never share viewer information, payment references, webhook addresses, tokens, staff logs, or private screenshots.
  • Sign out when using a shared or unattended device.

Review integrity

  • Verify the requested game, system, play choice, and payment bracket before approval.
  • Leave a request pending and contact the owner when information is unclear.
  • Never approve a request simply to bypass eligibility, pricing, or service availability.

Changes and explanations

  • Game or system replacements must remain inside the original payment bracket.
  • Do not alter the request choice, required amount, payment reference, or approval state to force a change.
  • Provide a truthful, professional reason for every denial, cancellation, correction, reschedule, or cleared schedule.

Scheduling and service controls

  • Record a game time only after the viewer, owner, and involved staff agree.
  • Turning services off blocks new submissions only; existing requests continue normally.
  • Reset the global cooldown only when the owner has authorized reopening requests.

Notifications and audit trail

  • Use Admin to confirm important Discord updates were delivered.
  • Retry an unresolved failure only after checking the error so duplicate messages are avoided.
  • All staff actions should match the request record and the message shown to the viewer.

When uncertain

  • Do not guess, erase information, or make an undocumented exception.
  • Keep the request in its current state and contact ⁅𝐓𝐡𝐲𝐓☣︎𝐱𝐢𝐜𝐆𝐚𝐦𝐞𝐫⁆ for a final decision.
  • Use the emergency service switch only when new requests genuinely need to be paused.
